### 관찰
1. **승인/거절 실데이터가 있었음**: 대기 5건, 승인 3건(큰금액, 항목30개, 총금액빈), 거절 2건(항목25개, 시각날짜). 배지 계산 색상(라이트: 대기 연회색, 승인 검정 바탕, 거절 붉은 계열 / 다크: 대기 어두운 회색, 승인 밝은 바탕, 거절 붉은 계열)이 서로 구분됩니다. v1 위험 요소(승인/거절 배지의 실데이터 확인)는 해소되었습니다. Task 012의 "데이터 없음" 기록은 현재 DB와 맞지 않습니다.
2. **`[TEST] 총금액빈` 행 총액이 ₩1,100,000**으로 표시됩니다(`null`이 아님). 행 이름과 달리 롤업 값이 채워져 있습니다. 따라서 Task 015의 "총 금액이 비면 `null`" 경로는 이번에도 실데이터로는 확인하지 못했고, Task 016의 임시 데이터 확인으로만 근거가 있습니다.
3. **768px 표**: 작업 열의 두 버튼이 세로로 쌓이고 견적서 번호가 줄바꿈되지만 잘리거나 넘치지 않습니다. 결함으로 보지 않았습니다.
4. **로그아웃 후 뒤로 가기**: 이전 목록 DOM이 숨겨진 상태(`display: none`, 0×0, `checkVisibility() === false`)로 남고 화면에는 로그인 화면만 보입니다. 새로고침하면 사라집니다. 로드맵 위험 요소의 "이전 목록이 잠깐 보일 수 있음"은 관찰되지 않아 캐시 헤더 조정은 하지 않았습니다. 같은 브라우저의 같은 사용자가 이미 본 화면이며 다른 사용자에게 노출되지 않습니다.
5. **`NEXT_PUBLIC_SITE_URL`은 빌드 시점에 반영됩니다**: `next start`에 값을 넘기고 빌드는 그대로 두었을 때 복사 값은 `http://localhost:3000`(폴백)이었고, 값을 넣고 다시 빌드하자 `http://localhost:3100`이 되었습니다. README에 이미 적혀 있는 동작이며, Task 017 기록의 "시작" 표현만 오해를 부를 수 있습니다.
6. **관리자 환경변수 누락**은 "로그인 항상 실패"보다 엄격하게 **폼 자체가 없습니다**. 로드맵 문구("로그인 항상 실패 + 안내")와 방향은 같고 더 안전한 쪽입니다.
7. **`Minified React error #441`**: 잘못된 노션 키 시나리오에서만 발생했고, `react-server-dom` 클라이언트의 `resolveErrorProd()`가 던지는 값(프로덕션에서 서버 오류 원문을 숨기고 오류 경계로 전달하는 일반 오류)임을 로컬 소스에서 확인했습니다. Task 016 기록의 "의도한 서버 오류 전달"과 같습니다.
8. **서버 로그 형식**: 노션 오류의 `[notion] listInvoices 실패: …` 줄은 한 줄이며 비밀 값이 없습니다. 같은 요청에서 `@notionhq/client warn: request fail {…}`(코드, 노션 안내 메시지, 요청 ID)와 Next의 `⨯ Error: 노션에서 견적서 목록을 불러오지 못했습니다.`(digest)가 함께 찍힙니다. 이 줄들에도 키와 견적서 내용은 없습니다.
9. **측정 방법 주의**: 클릭 후 접근성 이름이 바뀌는 버튼을 `getByRole('button', { name: /링크 복사/ })`로 다시 읽으면 이름이 "복사됨: …"으로 바뀌어 매칭이 끊기고 2초 뒤 복원된 문구를 읽게 됩니다. 앱 결함이 아니라 테스트 로케이터 문제였습니다.
