# Task 005: 노션 연동 계층 실데이터 검증과 페이지 연결 (F001, F011)

## 개요
`getInvoice`(노션 조회 계층)를 사용자의 **기존 노션 Invoices/Items DB**로 검증하고, 견적서 페이지가 `getInvoice` 결과만 렌더링하도록 정리합니다. 시드 스크립트는 쓰지 않으며, 테스트 케이스는 기존 DB에 제목이 `[TEST]`로 시작하는 행을 추가해 만듭니다(기존 행은 수정하지 않음). 이 행들은 Task 006~008의 PDF와 통합 테스트에서도 재사용하므로 Task 008이 끝날 때까지 유지합니다.

주요 결정:
- `NOTION_DATABASE_ID`는 Invoices DB의 `database_id`입니다. `data_source_id`를 넣으면 `belongsToInvoiceDatabase` 비교가 실패합니다.
- 404 HTTP 상태: ID 형식 오류만 `src/proxy.ts`에서 진짜 HTTP 404로 처리합니다. 형식은 맞지만 없는 ID, 휴지통, 다른 DB는 Cache Components 쉘이 먼저 전송된 뒤 `notFound()`가 실행되므로 404 화면 + noindex(HTTP 200)입니다. (Task 004에서 넘어온 항목)
- 항목 조회는 노션 API 평균 초당 3회 제한을 고려해 3개씩 묶음 조회합니다. SDK는 429를 기본 2회 자동 재시도하므로 재시도 로그(INFO `retrying request`)가 0회인지로 확인합니다.
- 캐시: `cacheLife("minutes")` = 클라이언트 stale 5분, 서버 재검증 1분, 만료 1시간.
- 총 금액은 사용자가 롤업(항목 금액 합계)으로 전환할 예정입니다. 전환 전에는 number 컬럼(비어 있으면 항목 합계로 대체), 전환 후에는 롤업 값을 읽고 25개 이상에서 값이 부정확하면 항목 합계로 대체합니다.
