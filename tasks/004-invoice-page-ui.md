## 테스트 결과
Playwright(playwright-core + Chromium)로 수행했습니다.
- 통과: 정상 순서(헤더, 메타, 표, 합계, 버튼), 더미 4종 콘솔 에러 0, 375px 카드형 목록(페이지 scrollWidth = 375), 768/1280px 표 레이아웃과 32행, Tab으로 버튼 포커스와 3px 포커스 링, 인쇄 미디어에서 버튼 `display: none`, 다크 모드 배경/글자색 구분, 운영 빌드에서 `/invoice/demo`가 더미 없이 404 화면.
- 실패 1: `/invoice/abc` 404 화면은 보이지만 HTTP 상태가 200입니다(운영 빌드도 200). Suspense 안에서 `notFound()`가 호출되어 응답이 이미 스트리밍을 시작한 것으로 추정됩니다. 확인되지 않은 원인입니다.
- 실패 2: 에러 경계의 "다시 시도"가 복구하지 않습니다. 서버 컴포넌트가 던진 에러에서 클릭 후에도 서버 재요청 없이 에러 화면이 유지됩니다. 이 Next 버전 문서(`error.md`)는 데이터를 다시 가져오려면 `reset()` 대신 `retry()`를 쓰라고 안내합니다. `src/app/error.tsx`가 `reset`을 쓰고 있습니다. `retry`로 바꾼 뒤의 동작은 아직 확인하지 않았습니다.
- 미확인: 스켈레톤과 실제 화면의 영역 위치 비교. dev 서버 응답이 빨라 스켈레톤 상태를 캡처하지 못했습니다.

### Playwright MCP 재검증: 404/에러 단계와 운영 빌드 (2026-11-19)
- 수정: `src/app/error.tsx`가 `reset` 대신 `retry`를 쓰도록 바꿨습니다(Next 16.4 `error.md` 안내). 404/에러 화면의 문구, 아이콘, 여백은 이미 견적서 페이지 톤이어서 변경하지 않았습니다. 에러 원문과 API 키는 화면에 나오지 않습니다.
- 통과(실패 2 해소): 임시로 첫 요청에서만 에러를 던지는 코드를 넣고 확인했습니다. 에러 화면(제목, 안내 문구, "다시 시도" 버튼, 원문 미노출)이 보였고, 버튼 클릭 후 에러 화면이 사라지며 견적서가 렌더되었습니다. 임시 코드는 제거했고 `TEMP-RETRY`, `demo-throw` 잔여 문자열이 0건임을 확인했습니다.
- 통과: `lint`, `tsc --noEmit`, `build` 통과.
- 통과: 운영 빌드(`build` 후 `start`)에서 `/invoice/demo`, `/invoice/demo-many`는 더미가 노출되지 않고 404 화면("견적서를 찾을 수 없습니다")이 표시되며, `robots: noindex, nofollow`가 있고 콘솔 에러·경고는 0입니다.
- 미충족(실패 1, 원인 확인됨): `/invoice/abc`는 404 화면이지만 HTTP 상태는 200입니다. Next 문서(`not-found.md`, `loading.md` Status codes)는 Cache Components에서 쉘이 먼저 전송되면 요청 시점의 `notFound()`는 상태를 바꾸지 못한다고 설명합니다. 체크리스트의 "응답 상태 404"는 현 구조에서 충족할 수 없으며, noindex 메타로 색인은 막힙니다. 기대값을 바꿀지, 구조를 바꿀지는 사용자 결정이 필요합니다.
- 통과(미확인 해소): 임시로 3초 지연 분기(`demo-slow`)를 넣고 같은 출처 iframe 375/768/1280px에서 1.2초 시점(스켈레톤)과 5.7초 시점(실제)의 영역 위치를 측정했습니다. 임시 코드는 제거했고 잔여 0건, `lint`, `tsc` 통과를 확인했습니다.
  - 768/1280px: 헤더 상단 48px로 동일(높이 64), 메타 상단 144px로 동일(높이 40 대 44), 항목 상단 216 대 220px(4px 차이).
  - 375px: 헤더 상단 32px로 동일(높이 64 대 60), 메타 128 대 124px, 항목 200px로 동일.
  - 항목 이후(합계, 버튼)는 항목 수에 따라 높이가 달라져 어긋납니다(3개 더미 기준 합계 상단 -37px(데스크톱), +88px(375px)). 스켈레톤은 표 높이를 192px로 고정한 근사치입니다.
  - 스켈레톤에는 버튼 자리가 없어 로드 후 맨 아래에 32px가 추가됩니다. 본문 위쪽 영역에는 영향이 없는 맨 끝 변화입니다.
  - 판단: "주요 영역 위치가 크게 어긋나지 않음"은 헤더, 메타, 항목 시작점 기준으로 충족합니다. 필요하면 스켈레톤에 버튼 자리를 추가하는 개선을 별도로 검토할 수 있습니다.
- 결정(사용자): `/invoice/abc`의 HTTP 상태 코드 200 문제는 Task 005(노션 실데이터 연동 시점)에서 함께 판단합니다. 그때까지 Task 004는 ✅를 표시하지 않습니다.
