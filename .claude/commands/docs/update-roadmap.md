# Claude 명령어: Update Roadmap

`tasks/` 작업 파일의 테스트 기록을 확인하고, 완료된 Task를 `docs/ROADMAP.md`에 ✅로 반영합니다.

## 사용법

```
/docs:update-roadmap          # tasks/ 전체 검사
/docs:update-roadmap 004      # Task 004만 검사
```

인자: `$ARGUMENTS` (Task 번호, 선택)

## 핵심 원칙

- **테스트 체크리스트 전 항목 통과가 작업 파일에 기록된 Task만 ✅ 처리합니다.**
- 코드가 다 작성되었어도 테스트를 하지 않았거나 실패 항목이 남았으면 ✅ 하지 않습니다.
- 코드 존재 여부나 커밋 이력만으로 완료를 판정하지 않습니다. 근거는 작업 파일의 기록입니다.

## 프로세스

1. **대상 선정**
   - 인자가 있으면 `tasks/<번호>-*.md` 한 개를 대상으로 합니다. 파일이 없으면 안내하고 중단합니다.
   - 인자가 없으면 `tasks/`의 `000-sample.md`를 제외한 모든 작업 파일을 대상으로 합니다.
   - `docs/ROADMAP.md`와 대상 작업 파일을 먼저 읽습니다.

2. **완료 판정** (작업 파일마다)
   - "## 테스트 체크리스트"의 모든 항목이 `[x]`인가
   - "## 테스트 결과"에 시나리오별 통과 기록이 있는가 (비어 있거나, 실패/미수행/보류 항목이 있으면 미완료)
   - 완료 기준의 `lint`, `tsc --noEmit`, `build` 통과 기록이 있는가
   - 하나라도 확인되지 않거나 판정이 애매하면 ✅ 하지 않고 사유를 보고합니다.

3. **ROADMAP.md 갱신** (최소 변경, 기존 문체와 형식 유지)
   - 완료 Task: 제목 끝에 ` ✅ - 완료`와 `(See: /tasks/XXX-xxx.md)`를 추가합니다. Task 003 형식을 따릅니다.
   - 완료 Task의 세부 구현 항목에는 ✅를 붙입니다.
   - 미완료 Task: ✅를 붙이지 않고, 남은 항목이 있으면 "진행 상황" 줄을 작업 파일 내용에 맞게 갱신합니다.
   - Phase에 속한 Task가 모두 완료되면 Phase 제목에 ✅를 추가합니다.
   - 마지막 완료 Task 다음 Task에 "- 우선순위"를 표시합니다. "의존성과 병렬 작업" 절을 확인해 병렬로 진행 가능한 Task가 있으면 함께 안내합니다.
   - 영향받는 "현재 구현 상태" 표 행을 갱신합니다.
   - Task 005 완료 시에는 `CLAUDE.md`, `README.md`의 "실제 노션 DB 검증 전" 문구를 "검증 완료"로 고쳐야 한다고 알립니다.

4. **보고**
   - 변경 요약: Task, 이전 상태 → 이후 상태, 근거 작업 파일
   - ✅ 보류한 Task와 사유 (미통과 시나리오, 비어 있는 테스트 결과 등)
   - 다음 우선순위 Task

## 제약

- 커밋하지 않습니다. 변경은 `git diff docs/ROADMAP.md`로 확인할 수 있게 둡니다.
- 작업 파일(`tasks/*.md`)은 수정하지 않습니다.
- 테스트를 대신 수행하지 않습니다. 테스트가 빠져 있으면 Playwright MCP로 먼저 수행하고 작업 파일에 기록하라고 안내합니다.
- 응답과 문서는 한국어로 작성합니다.
